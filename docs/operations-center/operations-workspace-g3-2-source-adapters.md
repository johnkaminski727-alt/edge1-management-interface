# Edge1 G3.2 — read-only current-source adapters

This increment distinguishes **monitoring-source freshness** from **component health**. On September 27 the operator demonstrated that current sanitized nftables and Fail2ban live-state files existed and were updating under root-owned private directories, while the network-defense aggregator still reported the corresponding component states as unknown. The older security/DNS/Spamhaus observation files were absent at their expected paths, despite the production Spamhaus nftables table being present.

G3.2 reads the **existing sanitized network-defense aggregator source records**, not the private root-owned files. Its fixed-key nftables and Fail2ban adapters report current, stale, unavailable or unverified source evidence without exposing source paths, raw JSON or sensitive diagnostics. If a source is current while the parent component state is unknown, the card still shows **unknown** and an amber warning, with a separate *Monitoring source: current* line and an explanation in the existing Evidence and next steps drawer. It never treats fresh collector data as proof of packet enforcement or correct firewall policy.

There are no new runtime privileges, file permissions, systemd units, timers or firewall mutations. The existing G3/G3.1 SSH-tunneled API remains bound to localhost. G3.2 modifies only curated presentation and adds tests ensuring that unknown components remain unknown, private strings cannot leave the summarizer, and absent/stale/unavailable sources never appear current.

**Deployment gate:** stage as a draft PR based on G3.1; run all G1/G2/G3 regression and reduced-archive installer preflight checks. Do not run `--apply` until exact pinned review and operator opt-in. Browser acceptance should open the Security tab, expand both firewall and Fail2ban evidence drawers, and confirm their source-status lines without assuming either is fully healthy. Direct privileged parsing of the underlying root-owned JSON requires a separate deliberately designed read-only bridge and schema review; this increment does not silently grant those permissions.
